## Решения владельца (13.10)

| № | Вопрос | Решение |
| --- | --- | --- |
| 1 | Кто видит общий Гант | Как в ТЗ §2: на общем Ганте все задачи по обычным правилам публикации (гость — только «публичные»). Скрытые задачи Product (`is_product_internal`) на общем Ганте **не показываются никому**, в том числе продуктам; они ведутся в планировщике Product (уточнено 13.10) |
| 2 | «Закрытые» задачи | Это скрытые. Завершённые задачи показываются |
| 3 | Фазы | Фазы = командные этапы, хронология: Продукт → Дизайн → Разработка (Фронт и Бэк вместе) → QA → Релиз |
| 4 | Исходный план (baseline) | Фиксируется при **утверждении плана релиза**. Плановая задача, назначенная в спринт, появляется на Ганте с пометкой «не согласовано». Баги и доработки не согласовываются, просто появляются в плане |
| 5 | Кто подтверждает переход этапа | Любой сотрудник продуктового отдела |
| 6 | Видимость предложений | Все предложения видны всем сотрудникам, приватных нет |
| 7 | Голоса | Голоса за предложения отдельны от голосов за задачи; приоритет задачи от предложений **не** наследуется |
| 8 | Статусы предложений | Новое → На рассмотрении → Принято / Отложено (причина) / Отклонено (причина). Принято → Запланировано **автоматически** при назначении спринта связанной задаче; вручную — если задача не требует разработки. Отклонено и Отложено можно вернуть на рассмотрение. Реализовано — вручную |
| 9 | Прогноз релиза в предложении | Не обсуждалось; по умолчанию — только по задачам, видимым читателю |
| 10 | Таблицы офферов | Удалить отдельной миграцией сразу после PR 1 |
| 11 | Старые плановые периоды | **Удалить** (13.10). Отдельный PR v2-10 после планировщика Product: убрать `capacity_periods` / `team_capacities` / `features.period_id`, старый автопланировщик и «Роадмап» по периодам. Удаление 8 периодов и 36 строк часов на проде — миграцией, при выкладке с подтверждением |
| 12 | Пустая ячейка ссылки при повторном импорте | Не удалять; в предпросмотре «нет в источнике»; удалять только по выбору |
| 13 | URL в описаниях текущих задач | Не переносить: текущие задачи можно удалить, владелец добавит их синхронизацией по новым правилам. **Удаление на проде — только при выкладке и после повторного подтверждения** |
| 14 | История удалённой записи | Стирать; копии не хранить. Остаётся одна запись аудита о факте удаления |
| 15 | Конструктор экспорта | Вариант А: отдельная страница «Экспорт»; слева каталог полей по группам, в центре выбранные колонки (перетаскивание, переименование), справа фильтры, сортировка и две группировки, внизу живой предпросмотр 50 строк и структура файла. Шаблоны: личные и общие от admin. Excel: заголовки групп с промежуточными итогами и сворачиванием уровней. Несколько ссылок одного типа — одна ячейка с переносами строк |

## Совместимость с MCP (ветка Codex `codex/roadmap-chatgpt-mcp`)

MCP — отдельный проект `mcp/`, ходит только в REST API. Его схемы используют `offer_ids`, фильтр `offer`, `stage_id`, `external_ref`, `/overview`, `/calendar`, `/analytics/summary`, `/features/:id/schedule`. Правила для наших PR:
- `offer_ids` принимается и игнорируется, фильтр `offer` даёт пустой результат — без ошибок 400;
- существующие ключи ответов (`/overview`, DTO задачи) не удаляются; новое добавляется рядом;
- Гант — новым эндпоинтом, а не заменой `/overview`.
