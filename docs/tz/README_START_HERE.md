# С чего начинать — пакет ТЗ и передача Claude → Codex

**Проект:** https://github.com/evgeniizhirov/rafinad-products

Это набор документов для реализации 11 согласованных доработок без перезапуска проекта с нуля. Зафиксированное состояние репозитория — 12 октября 2026 (`837998427564a181ab090261cf556c874cb01993`); перед началом проверить HEAD.

## Какие файлы читать

1. **`00_MASTER_TZ.md`** — полное продуктовое ТЗ, архитектура, 11 требований, правила, тестовые сценарии, открытые решения.
2. **`01_CLAUDE_STOP_AND_HANDOFF.md`** — короткая команда Claude: сохранить всё сделанное и передать состояние без расхода токенов на новый модуль.
3. **`02_CODEX_EXECUTION_PLAN.md`** — последовательность PR, зависимости и расписание совместной работы.
4. **`prompts/`** — отдельные готовые задания для Codex. Передавать по одному; приложить `00_MASTER_TZ.md` (или положить файлы в папку `docs/` репозитория).

## Первый безопасный запуск

1. **Не запускай два агента в одном рабочем каталоге.** Если Claude сейчас редактирует код — сначала завершить его сессию по короткому handoff-файлу.
2. Claude сохраняет все текущие незакоммиченные изменения в отдельную ветку и PR/commit; сообщает base SHA; без автодеплоя.
3. Передай Codex `00_MASTER_TZ.md` и текст `prompts/P01_votes_acl.md` для небольшого контрольного задания. Оно проверит, что Codex умеет работать с этим проектом и тестами.
4. Затем `prompts/P02_task_foundation.md` — общая основа, обязательна до крупных функций.
5. После общего ядра реализовывать план по зависимостям. Одновременно могут работать несколько агентов **только в разных ветках и при отсутствии конфликта изменяемых файлов**.
6. Каждый модуль — отдельный PR, после проверки merge в `main`, следующие ветки rebased.

## Приоритет при ограниченном бюджете токенов

Минимальная полезная поставка: **P01 → P02 → P03 → P05 → P06** (права, виды задач, календарь, баги/импорт, дашборд). В промежутках **P07** (API-ключи) и **P08** (экспорт) можно делать отдельными PR. Бюджеты (P04) и аналитика (P09) требуют более аккуратных расчётов и приёмки.

> Кодекс в этой нумерации P01..P09 работает по текстам из `prompts/`. Индексы полного ТЗ FR-01..FR-11 обозначают продуктовые функции, а не очередность работ.

## Правила без исключений

- Никакой публикации JSON Google Service Account, паролей, Bearer-токенов и других секретов в чат, коммиты, PR и логи.
- `npm run typecheck && npm test && npm run build` после каждого PR, с действительным отчётом, что запускалось.
- D1 remote migrations и Workers production deploy **только с явным разрешением владельца**.
- Не удалять исторические данные и старые API без миграционного плана.
- Если в ТЗ помечено «нужно согласовать», реализовать как настройку или подготовить интерфейс, но не скрывать произвольное значение в коде.
