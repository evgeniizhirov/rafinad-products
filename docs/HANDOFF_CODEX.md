## Архитектура

- **Worker** (`worker/index.ts`): свой роутер `worker/lib/http.ts` (`Router`, `readJson` с zod, `HttpError`, `json`). Отдаёт `/api/*` и статику клиента из `dist/client` (binding `ASSETS`, SPA fallback, `run_worker_first`).
- **Маршруты** `worker/routes/*`: `auth`, `admin` (пользователи, справочники, настройки, аудит), `catalog` (эпики, офферы, `/api/meta`), `features` (задачи, голоса, оценки, связи, комментарии, размещение), `merge`, `priorities`, `dashboard` (`/api/overview`, `/api/roadmap`, `/api/graph`), `planning` (мощности, предложение плана, алерты), `releases`, `imports` (синхронизация с таблицами). В стопке добавлены `calendar` (спринты, месяцы, расписание), `apikeys`, `exports`, `budget`, `analytics`; домен — `calendar.ts`, `budget.ts`, `xlsx.ts`, `exportTable.ts`, `analytics.ts`. Подробности по каждому модулю — `docs/IMPLEMENTATION_NOTES.md`.
- **Домен** `worker/domain/*`: `priority.ts` (рейтинг по голосам отделов), `capacity.ts` + `planner.ts` (планирование), `graph.ts` (циклы блокировок), `importer.ts` (предпросмотр/дифф импорта), `flatSheet.ts` (формат «одна таблица задач», пресет TaskFlow), `csv.ts`, `text.ts`.
- **`worker/lib/world.ts`** — загружает весь каталог одним batch и считает DTO, флаги (`hasFlag`: open/blocked/unvoted/unestimated), `isClosed`, `openBlockerIds`. Большинство GET-маршрутов строится поверх него.
- **Запись**: `tx(db, stmts)` = `D1.batch` (атомарно). Оптимистическая блокировка через `guardVersion` — вставка в `_guard` с CHECK, падение = откат всего batch → 409 `version_conflict`. Аудит — `auditStmt` (`worker/lib/audit.ts`) в том же batch.
- **Права**: роли `admin`, `product`, `department_lead` (+ гость без входа видит только `public`). `requirePerm(ctx, perms.X)`; голосует руководитель только за свои отделы (`department_memberships`). Видимость карточек: `draft` / `internal` / `public`.
- **Клиент** `client/src`: React 19 SPA, сборка esbuild (`scripts/build-client.mjs` → `dist/client`). Свой роутер (`navigate`, pushState/popstate), `useApi` + шина `invalidate()` (любая успешная запись перечитывает видимые данные), `mutate()` с тостами. UI-кит в `ui.tsx` (`Modal` с `dirty`-подтверждением, `useDirty`, `Field`, `Pill`…). Страницы — `client/src/pages/*`.
- **Локально**: `scripts/dev-server.ts` запускает настоящий код Worker на Node + `node:sqlite` (`scripts/sqlite-d1.ts` эмулирует D1, включая batch-транзакции).

## Команды

```bash
npm install                 # postinstall собирает клиент
npm run typecheck           # tsc для worker/, tests/, scripts/ (клиент tsc НЕ проверяет — нет @types/react)
npm test                    # tsx --test tests/*.test.ts — 121 тест на вершине стопки (claude/09-analytics)
npm run build               # сборка клиента (esbuild) — единственная проверка клиентского кода
npm run dev:node            # http://localhost:8788, БД .local/dev.sqlite, демо-данные + admin@rafinad.test (пароль печатается при первом запуске; можно задать ADMIN_EMAIL/ADMIN_PASSWORD)
```

Тесты используют `tests/helpers.ts`: in-memory SQLite со всеми миграциями + seed, вызовы `worker.fetch` напрямую.

## Что нельзя менять без миграции / плана

- Схему таблиц (`features`, `department_votes`, `feature_estimates`, `source_entity_links`, `import_*`, `audit_log` и т.д.) — только новой миграцией.
- `source_entity_links(source_id, entity_type, external_id)` и формат `last_values` — на них держится повторная синхронизация TaskFlow (3-way diff). Формулу ID `tf-…` (`derivedId` в `flatSheet.ts`: нормализованный текст задачи + исполнитель) менять нельзя: все 35 прод-карточек превратятся в «возможные дубли».
- Нумерацию `features.number` (RF-N) и id записей.
- Публичные/существующие API-маршруты — только расширять.

## Секреты и runtime-настройки Cloudflare (значения не копировать)

- `GOOGLE_SERVICE_ACCOUNT_JSON` — secret, JSON-ключ read-only сервисного аккаунта Google. Задан на проде 12.10, таблица TaskFlow расшарена; «Проверить подключение» успешно. Используется в `worker/lib/google.ts` (`serviceAccount`, `fetchSpreadsheet`), scope `spreadsheets.readonly`. Экспорт (P08) запрашивает scope `spreadsheets` с тем же ключом: целевую таблицу нужно открыть сервисному аккаунту как «Редактор», лист `Import` создать заранее. Остальные таблицы остаются «Читатель».
- `COOKIE_SECURE` — var, `"0"` только для локального http. На проде не задавать.
- `__FETCH` — тестовый хук, на проде не задаётся.
- Пароли пользователей — PBKDF2 (`worker/lib/crypto.ts`), сессии в `sessions`.

## Завершено

- MVP по исходному ТЗ: каталог (задачи/эпики/офферы/релизы), голосование отделов и рейтинг, оценки по ресурсным командам, планирование по мощностям, роадмап, связи и блокировки с проверкой циклов, слияние дублей, приглашения и роли, аудит, импорт из Google Sheets с предпросмотром.
- Коммит `8379984` (12.10):
  - пустые страницы при переходах — эффект возвращал Promise от `window.scrollTo` (Chrome 154) и React вызывал его как cleanup. **Правило: в `useEffect` всегда блочное тело `{ … }`**;
  - модальные окна: закрытие по фону только если нажатие началось на фоне, подтверждение при несохранённых изменениях (`dirty`), Escape — только верхнее окно, формы получают свежую версию записи;
  - плитки «Обзора» ведут в бэклог с фильтром `?flag=open|blocked|unestimated|unvoted` / `?status=…`, бэклог поддерживает `flag`, `tag`, `hide_closed`;
  - импорт: формат `flat` (одна таблица задач, пресет TaskFlow), предпросмотр из загруженного CSV для google-источника (`POST /api/import/sources/:id/preview` с `{ files: { flat: csv } }`), bulk `link_exact_duplicates` / `create_duplicates`, видимость новых карточек из настроек источника, статус у `flat`-источника следует колонке «Сделано», пока его не меняли в системе.
- Прод-данные (12.10, через D1):

  - категории: Исследование, KPI, Плановая;

## В работе / известные проблемы

1. **«Выбрасывает из редактирования отделов»** — воспроизвести не удалось. Исправлено то, что могло давать такой эффект (см. модальные окна выше); ждём повторной проверки владельцем.
2. ~~Прямая синхронизация TaskFlow~~ — сервисный аккаунт настроен 12.10, проверка подключения проходит. Кнопка «Из выгрузки CSV» остаётся как запасной путь.
3. **TaskFlow без колонки ID**: переименование или переназначение задачи даёт «возможный дубль». В таблице 4 пары похожих задач (строки 2/13, 6/29, 3/35, 26/37) загружены как отдельные карточки. Рекомендация владельцу — добавить колонку ID и указать её в настройках источника (`columns.id`).
4. Клиентский TypeScript не проверяется `tsc` — ошибки типов в `client/` ловит только ревью и runtime. Можно добавить `@types/react` и отдельный tsconfig.
5. Приоритет P1/P2/P3 из таблицы хранится тегами и в рейтинг не входит: рейтинг считается только по голосам отделов.
6. `npm`-реестр и Cloudflare API из облачной песочницы Claude были недоступны, поэтому деплой шёл только через Workers Builds, а D1 правился через MCP.
