# Проверка vNext — 13.10.2026

Объединены PR #13–23 (до `0ed9ed6`) и MCP (`655eb7f`). Пользователь разрешил проверку, исправления и выпуск в production. Отдельно подтвердил удаление старых периодов и доступности команд; 35 задач сохраняются.

Исправлено при проверке:

- Полное удаление задачи теперь стирает также историю комментариев, голосов, оценок, размещения и связей.
- Подтверждение удаления привязано к монотонной ревизии audit_log и проверяется атомарно перед удалением. Новая активность, включая дочерние записи, требует нового предпросмотра. Изменение любого журналируемого объекта консервативно отменяет старое подтверждение; интерфейс очищает введённый ключ.
- Повторное открытие этапа в тот же день определяется порядком событий, а не только датой.
- Диапазон Ганта включает задержанные сроки и прогнозы задач внутри спринтов.
- Одноимённые шаблоны экспорта имеют разные Google-вкладки с идентификатором шаблона. Числовые отчёты с группировкой сохраняют подписи групп отдельно от итогов.
- Повтор создания предложения при коллизии номера использует код ошибки транзакции.
- MCP больше не принимает удалённые фильтры офферов/периодов и поле offer_ids.

Проверено: 162 теста приложения, 14 MCP-тестов, TypeScript обоих проектов, frontend build и Worker dry-run. Локальный браузер: вход тестовым администратором, обзор, планировщик, конструктор экспорта. Production-данные для этих тестов не копировались.

## Порядок выпуска

До изменений production: миграции 0001–0011; 35 задач; офферы и их связи пусты; 8 периодов, 36 записей доступности, 0 задач с period_id. Точка D1 Time Travel и предыдущая версия Worker сохранены локально в `.local/pre-vnext-recovery.json` (не публикуется).

1. Добавочные миграции 0013–0017 применяются отдельно, до нового кода. На 13.10 этот шаг выполнен.
2. Выпускается новый код, совместимый с оставшимися старыми таблицами.
3. После проверки нового кода применяются 0012 и 0018. Не запускайте все новые миграции до выпуска совместимого кода.
4. Проверяются HTTP-маршруты, версия Worker, список миграций и сохранность количества задач.

До шага 3 возможен откат только кода; после удаления старых таблиц старый Worker несовместим со схемой. Восстановление всей базы через Time Travel требует отдельной оценки новых записей и согласования: это не автоматический rollback.

MCP выпускается отдельно и остаётся закрыт до настройки OAuth и персонального API-ключа. Сам факт публикации Worker не подтверждает работоспособность входа из ChatGPT.
